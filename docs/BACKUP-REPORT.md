## 一、结论

**验收通过（35/35），既有五套验收全部无回归（11/33/25/29/33）——累计 166 项断言全绿。**
这个功能的价值不在"能点一下备份"，而在于**灾难发生那一刻它真的能救回来**，而且**备份文件被拿走也解不开**。

## 二、为什么必须加密（设计前提）

数据目录里有四类东西：

| 内容 | 丢了会怎样 |
|---|---|
| `leadstack.db` | 服务器、检测项、告警规则、发布记录全没 |
| `master.key` | **所有 SSH 凭证永久无法解密**（库里有密文也没用） |
| `known_hosts` | 首次连接时会重新询问主机指纹 |
| `artifacts/` | 已上传的部署制品丢失（可能很大，可选备份） |

所以备份**必须包含 `master.key`**——但一旦归档泄露，等于把所有服务器的钥匙交出去。
因此归档强制加密，且**解密口令 `backup.pass` 被排除在归档之外**：单独存放，备份被拿走也解不开。

## 五、实现要点（几个关键决策）

1. **SQLite 快照不能用 `VACUUM INTO` 配只读连接** —— 实测被 SQLite 拒绝（`attempt to write a readonly database`）。改用 **SQLite Online Backup API**（源连接 `mode=ro + query_only`，512 页步进、可 ctx 取消），与 `VACUUM INTO` 一致性等价，绝不直接拷 `.db`（WAL 模式下直接拷会得到不一致的库）。
2. **1 MiB 分块 GCM**：契约 header 只有一个 nonce，为支持几百 MB 制品不整包进内存，载荷分块加密（chunk nonce = 基础 nonce 前 8B + BE counter，header JSON 作每块 AAD）。
3. **口令校验值**：GCM 认证失败本身分不清"口令错"和"文件损坏"，所以在 header 放 `HMAC-SHA256(key,"lsbak-verify")[:8]` 先验口令 —— 否则用户输错口令会看到"归档损坏"，去排查一个不存在的问题。
4. **恢复顺序**：解压临时 → 全量校验 → 受管文件 move 到 `pre-restore` → 放置新文件；失败自动回滚。
5. **启动时应用暂存恢复**：`config → EnsureDataDir → 应用暂存（此时未开库）→ 写 pid → store.Open`。失败**拒绝启动**并给三条人工处理指引——带着损坏数据启动比不启动更糟。
6. **版本闸门双处**：verify 与上传都校验 schema 版本；上传过新时会清掉刚写入的暂存目录，否则用户"上传成功但重启被卡住"。

## 六、集成期修掉的三个真问题

1. **部署模板拒绝中文路径**（devops 发现）
   `Render` 的路径变量按字节校验，中文部署根（`/srv/应用/`）直接被拒。本仓库名含「领栈」，本地 `make test-e2e` 的 M4 全线失败；CI 是 ASCII 路径所以没暴露。已改为按 rune 校验：允许 UTF-8 可打印字符，仍拒绝空白/控制字符/shell 元字符/`..`，并加 1024 字节上限。**这对中文用户是硬伤，不是测试环境问题。**

2. **我的验收脚本 jq bug**（sshmgr 定位）
   `(.data.backups // .data)`：对数组取 `.backups` 是 type error，而 `//` **不会**兜底错误 → 断言永远失败。改为 `.data.backups?`。同一个错误导致"恢复后凭证不可读"的假失败——我手工验证过凭证其实可读。

3. **Acceptance 脚本的 TMPDIR 陷阱**
   `make test-e2e` 会把 `TMPDIR` 指到仓库内的 `.e2e-logs/`，路径含中文 → 部署根校验失败。脚本已强制使用纯 ASCII 临时根。

## 七、已知限制

1. **`backup.pass` 丢失后备份永久无法解密**——这是设计取舍，不是缺陷；文档与 UI 都已醒目提示。
2. **恢复需要重启控制端**（API 路径是"暂存 + 启动时应用"）；控制台不能自行重启。
3. **「版本过新」无法在真实环境构造**（需要更新版本程序生成的归档），由单测覆盖 `ErrSchemaTooNew` 与 `code=schema_too_new`。
4. 上传恢复上限 1 GiB；超大同理需调整。
5. `currentSchemaVersion = 6` 是 `cmd/leadstack` 常量，新增迁移需手工 +1（`internal/store` 未导出 schema 版本）。
6. `artifacts/` 默认不进备份（体积大），需要时显式开启。

## 八、生产建议（重要）

- **把 `backup.pass` 与备份文件分开存放**：另一台机器 / 密码管理器 / 离线介质。同盘丢失会一起没。
- **备份文件本身也要异地保存**：控制端主机整机故障时，本地 `backups/` 一起丢失。
- **定期演练恢复**：至少每季度用备份在隔离环境恢复一次，确认能启动、凭证可用。没演练过的备份不算备份。
- Docker 场景：`/data` 卷包含库、制品与备份，但**卷级 tar 会把 `backup.pass` 一起打包**，等于备份+钥匙同袋——需单独拷出口令并分开保管。
